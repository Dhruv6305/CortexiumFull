CORTEXIUM 2.0: Ambient Intelligence Platform & Context-Aware AI
===============================================================

Part 1: Comprehensive Project Analysis (IEEE Paper Ready)
---------------------------------------------------------
1. What is the project/module about?
Cortexium 2.0 is a local, ambient intelligence and computer vision platform. It acts as an automated, real-time memory system that processes audiovisual feeds (like camera frames and microphone input) to identify people, detect objects, analyze scene context, and log conversations.

2. What problem does it solve?
It solves the problem of manual context tracking in daily life. Instead of a user having to remember who they met, what they discussed, or what hazards were present in their environment, the system passively and automatically records, analyzes, and organizes these real-world interactions into a structured, searchable database.

3. What is the main objective?
The primary objective is to create a continuous "memory and awareness" pipeline that fuses traditional computer vision with modern Generative AI. It aims to extract structured knowledge (identities, emotions, environmental hazards, and conversation summaries) from raw first-person data entirely on local hardware, ensuring privacy.

4. What are the main features/functions?
* Real-Time Computer Vision: Detects objects and crops faces from live frames.
* Identity & Emotion Recognition: Matches faces against a local database and estimates age, gender, and dominant emotion.
* VLM Scene Understanding: Uses a Vision Language Model to generate natural language descriptions of scenes, including mood and safety hazards.
* Conversation Logging & Summarization: Transcribes spoken audio, attributes it to identified faces, and uses a Large Language Model (LLM) to automatically summarize the interaction.
* Real-Time WebXR Dashboard: A React-based interface that displays active sessions, recognized people, image galleries, and conversation logs via WebSockets.

5. How does it work, step by step?
- Data Ingestion: Camera frames (encoded as Base64) and audio transcripts are sent to the FastAPI backend.
- Vision Pipeline: The model_loader passes the frame through YOLOv8 to detect environmental objects. It simultaneously uses DeepFace to extract faces, analyze emotions, and compute ArcFace embeddings.
- Identification: The extracted face embeddings are compared against a local database using cosine similarity. If a match meets a strict threshold (< 0.40), the identity is confirmed.
- Generative Analysis: Optionally, the frame is sent to an Ollama-hosted VLM (e.g., qwen2.5vl) for deep scene description.
- Data Aggregation: The session_manager groups these events (identifications, objects, text notes) into an active session.
- Summarization & Persistence: When a session ends, the summary_manager passes the conversation transcripts to an LLM to generate a concise summary. The data is saved to local JSON files and broadcast to the React frontend.

6. What technologies/tools are used?
* Backend: Python 3, FastAPI, Uvicorn, WebSockets.
* Computer Vision: OpenCV, Ultralytics (YOLOv8), DeepFace (ArcFace model).
* Generative AI: Local Ollama API hosting LLMs (e.g., llama3, qwen3) and VLMs (qwen2.5vl).
* Frontend: React 18, Vite, Tailwind CSS, Framer Motion.
* Storage: Local file system (JSON files for sessions/summaries, image files for face databases).

7. Who would use it and what are the main use cases?
* Target Users: Researchers in Human-Computer Interaction (HCI), professionals requiring detailed meeting logs, or individuals needing assistive memory technologies.
* Main Use Cases: 
  - Context-Aware AR: Feeding real-time environmental data to augmented reality glasses.
  - Assistive Memory: Helping users recall past interactions, names, and conversation details with specific individuals.
  - Automated Journaling: Creating a passive, daily log of social encounters and activities.

8. What are the inputs and outputs?
* Inputs: Raw camera frames (video/images), microphone audio streams (transcribed to text), and manual user notes via the UI.
* Outputs: Bounding boxes for objects, recognized person names with confidence scores, emotion labels, natural language scene descriptions, and structured JSON session summaries.

9. What is the main benefit or contribution of this module?
The main contribution is a privacy-preserving, entirely local multimodal pipeline. It demonstrates how to successfully chain deterministic computer vision (YOLO/ArcFace) with probabilistic generative AI (VLMs/LLMs) to create a highly accurate, real-time context engine without relying on cloud-based APIs.

10. What are its main limitations, if any?
* High Computational Cost: Running YOLOv8, DeepFace, and multiple Generative AI models concurrently requires significant local hardware resources (specifically high VRAM GPUs).
* Storage Scalability: The current implementation uses flat JSON files for database storage, which will suffer from performance bottlenecks as the user's memory log grows large over time.
* Face Recognition Constraints: ArcFace relies on strict thresholds to prevent false positives; it may struggle with extreme angles, poor lighting, or occlusions if the user does not manually register diverse images of a person.


Part 2: Project Description Summary
-----------------------------------
1. Executive Summary
Cortexium 2.0 is an ambient intelligence platform that transforms the first-person camera feed (POV) of a user into a continuous stream of structured knowledge. It acts on that knowledge in real time through adaptive XR overlays, an agentic AI orchestration layer, and persistent memory. Every interaction, recognition, and classification event feeds back into a self-improving model that makes the system smarter with every use.

2. Core Capabilities
- Live Person Recognition: Uses YOLOv8 for person detection and DeepFace for facial recognition.
- Voice Integration: Background microphone thread listens for introduction phrases (e.g., "I am [Name]", "My name is [Name]") using Google Speech Recognition to automatically register unknown faces in real-time.
- Activity & Object Detection: Real-time classification of activities and detection of objects in the environment.
- Adaptive Learning: Learns temporal routines, social memory, spatial awareness, and user preferences to provide proactive alerts and personalized experiences.
- Multi-Platform Support: Features a WebXR browser interface, a terminal CLI, and potential for mobile and Unity XR integrations.

3. System Architecture
- Input Layer: Processes POV camera feeds, audio from microphones, GPS location, and device sensors.
- Computer Vision Engine: Normalizes frames, classifies activities, recognizes faces, and analyzes gestures.
- Agentic AI Orchestrator: Dispatches events to specialist agents (Navigation, Social Context, Environment, Memory, and Adaptive Learning) using a finite-state machine.
- Backend Control Layer: Built with Python and FastAPI. It includes a Scene State Manager, a Rule-Based Decision Engine (YAML rules), and a WebSocket Event Bus for real-time communication.
- Data Layer: Stores user data, session logs, events, encounters, and face embeddings locally (JSON/SQLite/Supabase).
- XR Presentation Layer: The primary frontend is built with React, Three.js (WebXR), and Tailwind CSS for rendering AR overlays and dashboards.

4. Technology Stack
Layer                        | Technologies / Libraries
-----------------------------|----------------------------------------------------------
Backend                      | Python 3, FastAPI, Uvicorn, WebSockets
Computer Vision              | OpenCV, Ultralytics (YOLOv8), DeepFace (ArcFace)
Generative AI                | Ollama (llama3, qwen3, qwen2.5vl), SpeechRecognition
Frontend                     | React 18, Vite, Three.js, Tailwind CSS, Framer Motion
Storage & DB                 | JSON file storage, file system
